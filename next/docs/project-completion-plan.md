## 2. 完整流程与模型选择

```text
冻结环境与数据划分 → 初始模型评测 → 教师真实交互采集 → SFT
→ 学生失败分析 → 教师回放修复 → 再 SFT（先完成一轮有对照的回流）
→ 同一起点对比：E1 配方 GRPO / 加局部信用的 GRPO
→ 独立测试、多种子与成本对照 → 固定交付版本
```

**推荐新主线重新采集、从选定的原始学生模型做领域 SFT；旧 SFT/E1/E2/E3 作为历史基线保留。** 可以复用已验证的环境与训练组件，不绑定旧权重、数据量或训练配方；新对照必须共享同一协议和起点。

| 角色 | 选择 | 使用方式 |
|---|---|---|
| 正式教师 | **gpt-6-astra-2026-09-03，high 推理** | 已完成 2,000＋200 条；用于冷启动 SFT 及后续一轮教师修复 |
| 独立参考教师 | **gpt-6.1-sol-2026-09-29** | 已完成 2,000＋200 条及正式评测，所有既有文件原样保留 |

正式教师已按用户要求固定为 Astra，不预设它一定优于 Sol。后续数据回流与 GRPO 对照共享同一教师及学生起点；不能把与旧 E1 的差异归因于单个改动。

当前 `Qwen/Qwen3.5-2B` 是已后训练模型，项目中的 Baseline 指领域训练前的初始模型；4B 也建议使用后训练版本。[2B 模型卡](https://huggingface.co/Qwen/Qwen3.5-2B)、[4B 模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)

新版采集器已接通用户提供的 ModelHub `crawl`：Sol 的原生 tools＋推理在该网关不受支持，采用 `high` 推理＋严格 JSON 动作 schema，再交由共享守卫执行。已通过真实多轮轨迹、截断拒收、usage 留档及学生模板验收；不依赖教师 logits 或私有推理文本。此适配不能称为原生 Responses/function calling。[官方接口说明](https://developers.openai.com/api/docs/guides/function-calling)

Astra 与 Sol 均已完成相同结构化动作下的各 2,000＋200 条合格示范，两个教师不混合计数；方法与结果见[教师阶段总结](teacher-collection/README.md)。初始示范可反复训练，后续失败回流仍需教师生成修复轨迹，SFT 参数优化及学生 GRPO 本身不调用教师。

### 数据现状与推荐规模

本地已有 `data/sft/` 800＋200 条，以及 `data/sft_pure_v4/all.jsonl` 1,192 条；后者包含前者全部任务，合并后仍为 **1,192 个独立任务**，不是截图中的 2,000 条训练轨迹。Pure V4 与现有 GRPO 训练池重叠 6 个任务，属于训练内部重叠；不应声称这两池完全隔离。历史 2,498 条原始采集是 metadata 记录，本地对应 raw 文件不存在。

以下为**实施默认预算，不是已证明的最佳数量**；所有成功轨迹按验收、去重、长度过滤后的可训练条数计。

| 项目 | 推荐规模 | 口径与扩量条件 |
|---|---:|---|
| 训练候选池 | **已冻结 6,000 题** | 教师候选 4,000、GRPO 2,000；另有 3,977 道隔离的训练备用任务，见数据准备结果 |
| 教师试采 | 同一批 100 题/候选模型 | 来自训练池，协议冻结后合格样本可复用 |
| 冷启动 SFT | **目标 2,000 条训练＋200 条独立验证轨迹** | 已另留 800 道验证采集候选；先做 1,000/2,000 条训练对照，有持续收益才扩量；验证轨迹只看 loss |
| 失败修复 | **首轮 300＋次轮 200 条** | 训练池每轮先采学生 1,000 题×2 次；按真实失败覆盖调整，不凑数 |
| 普通增量 SFT 对照 | 约 500 条 | 与修复组匹配教师、任务难度、监督 token 和更新预算，条数可不同 |
| GRPO | **2,000 个候选任务，每组 4 条 rollout** | 先用 500 题×4 次诊断可学习比例；8 条/组作为后续预算对照，不默认翻倍 |
| RL 更新预算 | 小试 50–100，正式先设 500 步 | 开发集仍改善且预算允许时统一扩至 1,000；相同对照使用相同选模规则 |
| 在线开发集 | **300 题** | 固定分层；其中固定 50 题作高频检查，完整 300 题用于选模 |
| 新锁定测试集 | **1,000 题** | 比旧建议 500 题更适合评估几个百分点的差异；不用于选模或回流 |
| 历史回归集 | 原 Final-200 | 单独报告，不能继续冒充未见测试集 |
| 人工判分校准 | 100 条分层轨迹 | 来自开发集，覆盖成功、失败、裁判争议 |
| 局部信用小试 | 64 个状态×2 动作×4 次续跑＝512 条分支 | 先验证回放可靠性和估计噪声，再进入在线训练 |
| 关键 RL 对照 | 每组 3 个训练种子 | 不能用同一 checkpoint 多次评测代替重新训练 |

先冻结划分，再采集。SFT 验证、开发、测试互相独立且不进入训练；测试按商品/近重复需求分组隔离，也排除历史训练与分析用题。类别/约束分层保持目标分布；只有显式留出类别才称为跨类别泛化。SFT 验证是成功示范集，其 loss 不能代替完整任务成功率。

2,000 条成功训练轨迹需要的尝试数取决于验收率：50% 时约 4,000 次、70% 时约 2,860 次，另计验证轨迹与重复/超长剔除；先试采再估算。测试 1,000 题、成功率约 70% 时，独立任务近似 95% 区间半宽约 2.8 个百分点（200 题约 6.4）；正式比较用逐题配对区间，相关任务按组处理，不保证小幅提升显著。

新版 `agent.py collect` 已实现共享执行、冻结角色与留出校验、唯一可训练任务计数、验收后领域配额和可续采证据。两位教师的各 2,000 条训练及 200 条验证成品均已全量复核，训练/验证与各自留出无重叠；SFT 已完成；一轮失败回流已实现真实前缀回放、教师接管、后缀 mask 与增量数据对照，正在执行。

## 3. 三个实施阶段

### P0：统一评测

- 保留 E1 执行快照和历史结果；新主线先冻结执行协议，初始 RL 对照关闭 E3/TRACE。已有模型可同入口重评作背景对照，核心消融从同一开发集选定 SFT 起点开始。
- 冻结环境、工具、守卫、终止和 token 预算。旧 Chat 没有训练侧相同的累计 response 上限；若统一预算，单独版本化并重评所有对照，保留原历史表。
- 按上表冻结开发/测试与训练池；排除既有训练源（含 Pure V4），测试题及其改写、修复数据不得回流。
- 严格成功仍要求完整 `gold_purchase` 且 `reward_valid=true`，失败保留在分母。另报硬约束满足率、错误购买、循环、成本与逐题得失。
- 人工抽查上表规定的分层轨迹，校准 API 裁判；隐藏模型身份和原分数，要求引用事件证据。Rubric/过程分与严格成功分开报告。

**验收：** 协议可复现、数据无泄漏、判分可核验。最终测试在方法与候选冻结后运行；1,000 题也不保证能辨别小幅提升。[评测实践](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

### P1：一轮失败数据回流

固定 S0 在未用于冷启动的训练候选题上执行，定位可验证接管位置，真实回放后由 Astra 续写。目标约 300 条严格成功修复；只监督教师后缀。第二轮不自动安排。

从独立训练备用池采集同数量、同领域分布的普通成功示范作为对照。两组混入相同原始 SFT 示范，从相同 S0 训练，匹配更新次数并记录实际监督 token 与 GPU 时间；开发集选模时保留 S0 作为候选。详见[实施方案](data-reflow/README.md)。

**验收：** 真实回放一致、失败前缀不被监督、普通增量对照完整、结果可追溯。属于借鉴 [DAgger](https://proceedings.mlr.press/v15/ross11a.html) 的教师纠错 SFT，不宣称完整实现其算法或理论保证。回流无收益时仍可从 S0 进入 GRPO。

### P2：局部信用分配

**问题：** E1 保留了失败，但整段轨迹共享序列优势；仍需检验哪些动作值得加强或抑制。

**方法：** 在同一个决策前状态改变当前动作，再由同一冻结学生续跑，估计动作对最终结果的影响。

- 先选训练池中约 **64 个决策点**，覆盖成功与失败。原动作与一个学生采样的替代动作各续跑 4 次，约 **512 条分支**；保持相同剩余预算。
- 用平均 `training_return` 估计动作价值 `Q`；记录方差、回放率和无替代动作的比例。缺少完整可核验配对时不加局部信用，主轨迹仍按 E1 处理。
- 小试可靠后，仅向选中动作的 assistant token 加入 `λ × clip(Q原动作 − 两动作平均Q)`；其他优势与 tool mask 保持原规则。初始覆盖约 10% 轨迹，每条至多一个决策点。
- 分支在 rollout 阶段完成，使用本次更新前同一策略；不跨版本复用 Q，不用教师续跑冒充学生价值。终局奖励、组筛选和选点规则固定。
- 先跑 **50–100 次更新**验证信号、显存和成本，再决定是否跑满 500 步；`λ=0` 应退回基线。

这是有噪声的局部优势估计，不保证因果识别或效果提升。已有 TRACE 可复用 turn/token 边界并作离线参考，但目标商品似然不等于购物进展；无需先训练 PRM。[TRACE 适用边界](https://arxiv.org/html/2607.13988v1)、[执行回放信用审计](https://arxiv.org/html/2608.19760v1)

## 4. 实验对照与代码复用

| 组别 | 做法 | 要回答的问题 |
|---|---|---|
| 历史对照 | 保留原 SFT / E1，必要时同入口重评 | 与历史成果如何衔接？ |
| B / S0 | 原始学生 / 新采 2,000 条轨迹的 SFT | 新主线冷启动收益是多少？ |
| S-general | S0 + 同教师普通成功轨迹继续 SFT | 普通增量数据带来多少收益？ |
| S-repair | S0 + 一轮修复数据 SFT | 定向回流是否更有效？ |
| R-outcome | 开发集选定 SFT + E1 配方 GRPO | 做好 SFT 后，RL 是否仍有价值？ |
| R-local | 同一开发集选定 SFT + 局部信用 GRPO | 信用分配是否产生增量收益？ |
| R-budget | 同一起点，纯 E1 配方使用相当的计算预算 | 收益是否仅来自更多计算？ |

S-general/S-repair 固定教师、原数据回放、样本数量和更新预算，匹配领域分布；修复后缀导致监督 token 和任务难度仍有差异，分别报告，不宣称完全等价。R-outcome/R-local 开发小试后冻结方法，最终各做 **3 个配对训练种子**；等更新与等计算预算分别比较。要宣称数据回流收益稳定，SFT 对照也需多种子。

最终模型按开发集选定；报告每种子分数、配对差值区间、关键失败率及成本。训练种子与测试任务的波动分别分析；不反复看测试集调参。若增强 SFT 更好，允许交付 SFT 并记录 RL 的限制。

| 模块 | 可复用 | 需要补充 |
|---|---|---|
| 采集 | 新版多轮 API、共享守卫、唯一任务计数、冻结划分及可续采证据已完成 | 前缀回放与接管、修复数据验收、补齐调用成本审计 |
| SFT | tokenizer/template、LoRA 训练器；旧数据/权重可选 | 教师续写的监督范围、混合数据版本；原实现默认监督全部 assistant |
| 评测 | `evaluation/`、Rubric、轨迹与 HTML 报告 | 新划分、裁判校准、统一比较和成本统计 |
| GRPO | E1、veRL、`trace.py` 边界、`compat.py` 接口 | 分支采样、局部 Q、优势注入与验证 |
| 运行 | 日志、后台监督、恢复、导出、HDFS 归档 | 统一实验状态与清晰配置；结束或可捕获异常后恢复双卡保活 |

Pure V4/课程入口先复用校验能力，不同时更换课程配方。新增功能沿用现有训练链路，不扩展浏览器、多 Agent 或新训练框架。

- **GPU：** 双 H100 执行已验证的 2B 配方，分支复用 rollout 服务；不额外常驻教师。现有 GRPO 峰值约 59.5 GiB/卡，4B 必须先测显存，双卡不能简单视作单块 160GB。
- **时间：** 历史 500 步约占用双卡 10–11 小时；6 个 RL 运行粗估 60–66 小时，另加分支、SFT、评测和预算对照。新配方先实测后排期。
- **归档：** 保留选中与最终检查点、模型、完整轨迹、诊断、数据/源码哈希；清理前回读验证。保活负载不计为训练效率，worker 被回收也无法靠进程脚本恢复。
- **交付：** 稳定执行入口、冻结实验清单、统一结果表、可回放案例和模型工件。案例同时包含改善与退化，成本包含失败尝试。
