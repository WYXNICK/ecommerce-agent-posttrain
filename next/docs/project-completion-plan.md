## 2. 固定资源与数据

- **学生：** Qwen/Qwen3.5-2B，revision 以[execution.json](../configs/execution.json)为准；这是领域训练前模型，不是未后训练的预训练基座。
- **教师：** gpt-6-astra-2026-09-03，high；Sol 的 2,000＋200 成品及评测独立保留。已有示范可重复用于训练，无须重复调用教师。
- **资源：** 两张 H100 80GB；LoRA、BF16、动作 token 投影和双卡负载均衡。吞吐看真实更新耗时，保活负载不算有效计算。

| 独立划分 | 数量 | 用途 |
|---|---:|---|
| 教师候选 | 4,000 | 示范采集、训练失败回流 |
| GRPO 任务池 | 2,000 | 在线交互采样 |
| SFT 验证候选 | 800 | 验收200条独立验证轨迹，只看验证loss |
| dev | 300 | 开发、选模、诊断 |
| test | 1,000 | 固定模型比较，不回流训练 |
| 训练备用 | 3,977 | 明确记录用题后扩量 |

100题教师试采、50题开发检查均为对应集合子集，不额外计数。候选任务数不等于成功轨迹数。商品与近重复组隔离不是跨环境泛化，静态规则也不等于逐题人工语义认证。

## 3. 核心设计约束

1. 采集、训练 rollout 与评测共享执行协议：Environment v2.1 / Reward v3 / Observation v2 / Tools v2；最多35步，固定上下文与输出预算。
2. 严格成功必须有完整、可验证的 `gold_purchase`；基础设施故障和模型失败分开。教师验收率与正式成功率分开报告。
3. SFT只监督动作；纠错只监督教师后缀并混合原示范。两组增量对照从同一S0开始，任务难度、监督token及GPU时间并非完全相同。
4. GRPO训练奖励、有效组筛选和优势计算一致；评测保持原Reward v3。每50步保存、完整dev评测；起点参与选模，无增益时允许保留SFT。
5. 主线500次有效更新，异常数值或无法安全继续时退出；不按一次dev波动临时改预算。独立会话运行，检查点先校验备份开发机，再归档外部存储。
6. 原始轨迹、配置、模型哈希、训练日志与逐题评测都保留；总结只写目的、方法、结果和局限。代码与简明结果入Git，权重和长日志外部保存。

## 4. 结论与后续边界

当前证据支持领域能力的大幅获得，以及GRPO在本轮随机采样协议下提高单次可靠性；test成功率的小幅增益尚未达到配对显著。具体得失见[核心结果](../../docs/results.md)。多训练种子、独立新留出、人工完整语义审计与实际费用结算均未完成，不写成既有成果。

后续继续Reward研究时，复用现有环境、数据、SFT起点和训练执行器，针对训练池中的可验证问题增加一个独立配方；先验证资格/奖励/优势一致性，再运行训练和dev选模，最后冻结候选评测。不用test失败题做修复数据；多轮观察后的test比较按探索性复用解释。
