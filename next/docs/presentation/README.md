# 简历项目表述与证据

## 推荐定位

**电商任务执行 Agent：约束遵循与强化学习优化。** 主线是把用户的预算、规格与商品偏好转化为可靠的多步执行策略。以“失败数据补足行为 → 在线学习提高执行可靠性 → 成功率与交互效率双提升”组织贡献，突出小模型完成任务的能力。场景基于ShopSimulator，个人工作聚焦后训练与执行链路。

正文顺序为数据闭环、在线学习、策略能力分析、端到端结果。pass@1/pass@8放在训练收益分析中，最后以test1000成功率与交互效率收尾；无需在简历正文展开统计局限和实验时间线，相关口径在下文保留用于面试复盘。

[可直接插入原简历的 LaTeX 条目](project-entry.tex)是推荐正文，沿用用户模板的 `\projectsubsection` 与 `itemize`。起止日期留空，按实际填写；未改动原简历其他经历，也未编译完整 PDF。建议放在 Relax 开源贡献之后，与其“大模型多模态 RL”形成互补，突出本项目的数据回流和可靠性评测。

## 面试时保持的口径

- 环境、Reward v3和基础算法有开源来源；个人工作重点是新版数据隔离、真实失败回流、训练/采样对齐、失败处理、双卡执行和成体系的结果验证。不宣称提出了新GRPO算法或自研信用分配算法。
- 正式测试与开发集采样诊断分开报告。测试增益1.2个百分点的单次配对检验未显著（p=0.2242）；开发集随机pass@1的配对区间不跨0，但不等于多训练种子稳定提升。简历直接给测得结果，不写“全面提升”“显著泛化提升”。
- pass@k用于解释训练收益：修复SFT的pass@8高于pass@1，说明存在可采到成功但单次执行不稳定的任务；GRPO主要改善单次采样可靠性。该诊断实际在四个模型训练后补做，不能写成当时启动GRPO或停止训练的依据；实际按500次有效更新训练、开发集严格成功率优先选模。它支持训练路线的合理性，不证明SFT已饱和或GRPO已达最优。
- 严格成功是可验证的完整目标购买终局，不以语言回答质量、平均奖励或任意买到商品代替。平均步数下降与成功率一起报告，不推导未经测量的上线收益。
- 只写已完成的有效主线；局部信用、稳定终局、4×4、SDPO等探索不列为已验证增益。探索证据继续保留，需要讨论实验取舍时再解释。
