# 终局奖励 GRPO（R-outcome）

## 目的与当前状态

检验定向修复 SFT 后，在线强化学习是否仍能提高任务完成率。本阶段从 **S-repair step 72** 开始（dev300：226/300，75.33%），已完成 **500 次有效更新**；选中 step 500，dev 228/300。详见 [结果汇总](results.md)。实时状态集中在 `next/outputs/grpo/outcome/status.json`、`progress.json`，不在本文重复更新步数。


## 固定方法

| 项目 | 设置 |
|---|---|
| 数据 | 冻结 GRPO 池 2,000 题；与验证、开发、测试及外层旧评测隔离 |
| 在线采样 | 每题 4 条，每次更新 2 个有效组；temperature=1、top_p=1，直接按当前策略采样 |
| 奖励 | 可验证终局直接使用 Reward v3；模型导致的非终局失败给 −0.65；基础设施失败、不可验证奖励过滤整组 |
| 优势 | `A = training_reward − 同题组内均值`，不除组内标准差；同一轨迹的全部动作共享该优势 |
| 动态采样 | 用同一 training_reward 筛除等分组；最多采 8 批补齐有效组；连续 10 次无信号则停，不能虚增更新次数 |
| 优化 | veRL 0.8 的 clipped policy loss；clip=0.2，token mean；LoRA r16/alpha32/dropout0；LR=1e−6，15 次线性预热，梯度裁剪1；每批一次更新，无额外 KL、过程或长度奖励 |
| 双卡 | 两个 BF16 actor 副本同步梯度，按动作历史长度平衡工作量；vLLM 驻 GPU0，预留25%显存，8路采样；训练侧使用 FLA 线性注意力、融合门控 RMSNorm、SDPA、梯度检查点，只投影动作位置的词表 logits |
| 选模 | 每50步完整 dev300；依次比较严格成功数、Reward v3、较少动作数、较早步数；SFT 起点也参与，RL 无收益时保留 SFT |
| 保存 | 每50步保存 adapter、优化器、随机状态、采样顺序与训练指标；最终导出选中模型及第500步模型，保留可恢复的完整训练状态 |

复用 E1 的失败分类、终局训练奖励和动态采样思想；这是新版独立实验，不能与旧 E1 的200题成绩混在同一对照表。温度1与不截断概率尾部用于保持采样概率与优化策略一致；不是旧实验配置的逐字重跑。

### 为什么按动作轮次组织训练

采样直接调用被冻结的 `run_episode`，与正式评测共用守卫、观察投影、预算及终止条件。vLLM 返回**真实输入 token、生成 token 和原始 logprob**，入口逐条核对输入与冻结模板一致。

每个动作以当时完整历史为条件计算 loss；历史与工具观察只作输入，不作标签，生成出错或超长的动作也保留。这样避免把解析后的工具调用重新编码成伪造的生成 token。不同动作的 loss 按全局动作 token 数合并，两卡梯度求和，数学上对应同一轨迹终局优势的 GRPO 目标；它没有引入步骤奖励或局部信用。重复计算历史前缀会增加训练开销，实际耗时和 token 单独记录。

训练复用 veRL 的策略损失，并用精简执行器对接新版精确逐轮输入；**不是旧版 veRL RayPPOTrainer 入口的直接重跑**。第一批正式数据同时校验采样/训练 logprob 差异、有限梯度和显存，不另跑多轮小规模试验。

加速只改变计算内核和动作在两卡间的分配，不改变动作标签、优势或全局 token 归一化。FLA 0.6.0 仅注入训练进程，推理与环境依赖保持冻结；依赖固定在 `scripts/grpo/requirements.txt`，外部目录 `SHOP_GRPO_KERNELS` 下的 `site/` 放安装包、`wheels/` 保留原始 wheel，随运行源码一同校验归档。短序列与4,096 token 序列的前向/梯度相对误差检查通过（均低于0.6%）；BF16 结果不要求逐位相同，正式训练仍须通过采样/训练概率一致性检查。`input_tokens_by_rank` 与实际更新耗时用于核对负载和吞吐，不能用保活利用率代替。

## 运行与证据入口

- 配方：[`configs/grpo.json`](../../configs/grpo.json)；入口：[`scripts/grpo/launch.sh`](../../scripts/grpo/launch.sh)。传入冻结运行环境、S-repair、工作目录及输出目录；机器地址不写入源码。
- `outputs/grpo/outcome/train.log`：唯一训练主日志；`metrics.jsonl` 与 `progress.json`：有效更新、奖励、有效组、clip、采样/训练概率差异、耗时。
- `outputs/grpo/outcome/tensorboard/`：原生 TensorBoard 事件；开发机端口 **6016** 的 `R-outcome` 分组（同时保留 SFT 对照分组）；`dev/step-*/`：各检查点的完整300题轨迹与汇总。
- `outputs/grpo/outcome/rollouts/`：按生成批次压缩保存全部训练轨迹、动作 token、logprob、失败及训练回报，包含被过滤的样本。
- `run.json`：输入模型、任务池、配置、实现和运行环境指纹；`selection.json`：开发集选模；完成后 `results/grpo/outcome/summary.json` 与本目录 `results.md` 为最终汇总。

**评测模型以精确的 SFT 基座＋adapter 为准。** BF16 合并导出作为便捷副本单列，未经同协议核验不能替换已评测的 adapter 策略。中断时入口支持 `--resume <检查点>`，使用新输出目录保留原证据，并恢复优化器、随机状态、采样位置和更新编号。

检查点先经 SHA256/文件清单校验复制到**开发机 `/tmp`**，收到确认后继续；独立归档器上传 HDFS，配额不足时保留本地并重试。模型、源码快照、训练日志、TensorBoard 和评测证据分别归档；Git 仅提交实现、配置和简明结果，不上传权重和海量轨迹。

监督进程独立于 SSH；训练、评测及备份全部完成后，若训练进程仍超过 60 秒未退出，则清理退出阻塞并继续导出；未完成的训练不适用该规则。结束或失败时回收本阶段子进程并恢复双卡保活。训练期间监控 GPU/SM 利用率并在空闲时补充小核负载；保活负载不计作有效训练效率，也不能保证每个瞬时采样都高于阈值。

## 什么时候停止

- **正常停止：完成500次有效参数更新。** 每50步进行 dev300 评测；本轮不采用按开发集分数提前停止的规则，也不因一次分数上升或下降临时改变预算。
- **异常停止：** 连续10次有界补采仍无法组成有效训练批次，或发生非有限梯度、训练/环境/推理服务退出、开发机检查点备份失败等无法安全继续的问题。HDFS 配额不足时，已校验的开发机副本保留并异步重试上传，不因此中断训练。
- **最终交付：** 从 SFT 起点及50/100/…/500步中按冻结的 dev 规则选优，保留选中模型和最终模型；完成导出、日志归档后恢复双卡保活。异常退出也恢复保活。训练集奖励和开发集选模结果均不替代最终测试。

## 验收与结论边界

关键检查覆盖：模型失败可学习、基础设施失败不参与、组内中心化、动作 token 身份与 logprob 一致、双卡全局 token 归一化。每次更新记录梯度及数值异常；首批采样/训练概率明显不一致时停止，避免带错误继续跑。

本轮是**单种子、开发集选模**。开发集提升不是最终泛化证明；最终 test1000 保持锁定，后续按总计划冻结对照后统一评测。训练没有自动“保证提升”，也不会为了得到好看的分数更换测试口径。
