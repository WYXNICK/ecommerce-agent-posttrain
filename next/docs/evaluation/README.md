# 冻结测试集对照

**状态：运行中。** 本阶段测量从原始学生、SFT 到终局奖励 GRPO 的最终泛化表现，不用测试集选择检查点。

## 固定模型与方法

| 模型 | 身份 | 处理 |
|---|---|---|
| Baseline | 冻结 revision 的原始 Qwen3.5-2B | 复用完整 test1000 |
| 教师 Astra | gpt-6-astra-2026-09-03，high | 复用完整 test1000 |
| 初始 SFT（S0） | dev 选中 step750 的合并模型 | 新评测 |
| 修复 SFT（S-repair） | dev 选中 step72，GRPO 起点 | 新评测 |
| GRPO step400 | 修复 SFT 基座＋原始 LoRA | Reward 最优次候选，新评测 |
| GRPO step500 | 修复 SFT 基座＋原始 LoRA | dev 成功率规则主候选，新评测 |

- 同一冻结 1,000 题、Environment v2.1、Reward v3、Action Guard、观察和预算；学生关闭 thinking、temperature=0，每题一次有效模型行为。模型失败保留分母，基础设施失败不得冒充完整结果。
- 两张 H100 各服务一个模型，每模型 8 路并发；两个批次完成四个新增评测。并发只改变调度，不改变任务、动作、评分或预算。
- GRPO 使用精确的基座＋adapter，不将 BF16 合并副本替换已验证策略。模型权重、adapter 和已有结果在开始前按 SHA256 固定于 [评测清单](../../configs/test_comparison.json)。
- Baseline 源码指纹较早；已核对环境、奖励、任务、观察、学生模板与执行器未变。变更涉及教师配置、采集来源以及传输重试/审计。保留原始指纹和证据，不伪装为重跑。Astra 与当前执行指纹一致；教师推理预算不同，仅作参考。

## 报告与完整性

报告全部六个模型的严格成功率、平均 Reward、平均步数、错误购买/循环、token 用量及同题得失。主要对照为修复 SFT→GRPO step500，step400 同时公开；不根据测试成绩只保留更好的版本。配对检验只作描述，明确单种子及多重比较限制。

复用结果校验任务 ID、完整分母、基础设施状态及原始轨迹哈希；新增结果从 raw 重新计算核对。原始逐题结果、服务日志及 GPU 监控保留在 `next/outputs/evaluation/test-comparison/`；完整证据复制到开发机 `/tmp` 校验后归档 HDFS，Git 仅存实现、冻结清单和汇总。

评测由独立后台监督进程运行；正常或失败退出均恢复双卡保活。保活负载不计为有效评测算力。原始结果按模型分目录保存，不与开发集结果或历史 E1/E2/E3 混合。
