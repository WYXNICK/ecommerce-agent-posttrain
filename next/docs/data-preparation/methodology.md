主划分共 8,100 题，加训练备用共 12,077 题；两个子集不能再次累加。新任务清单仅包含 `task_id`，可供现有采集入口读取，不把目标商品或评分答案传给模型。

数量目标仍是 **2,000 条可训练 SFT 轨迹、200 条验证轨迹、两轮约 300＋200 条修复**。4,000 道教师候选不保证产出 2,000 条合格轨迹；完整采集会报告验收率和配额缺口，必要时另行审阅备用池扩量方案。100 题子集可用于教师对比，并非必须追加的试跑阶段。验证候选从原计划的 500 题增至 800 题，为失败与长度过滤留余量；未成功的验证题也不能转入训练。

## 筛选依据

1. **忠实读取运行时任务。** 从项目内置 `items_eval_train.json` 出发，直接复用环境的 `load_products` 和 `get_goals`，得到 23,421 个任务；不假定原文件行号永远等于 task ID。校验源文件与冻结环境、搜索索引的产品哈希一致。
2. **检查任务可评分。** 目标商品必须存在于搜索索引；标注规格轴可解析、规格可选、价格可确定；按目标规格静态购买须得到 `gold_purchase` 且 `reward_valid=true`。有价格提示而现有规则不能解析预算的任务，本轮保守排除。
3. **补充明显的数据问题筛选。** 排除直接颜色冲突、客服报价/订金等非成品规格、零容量占位规格、损坏文本。颜色检查兼顾拼色、常见别称，对否定或相对描述不强行作字面判断。未修改源题、环境或奖励规则。
4. **隔离历史与重复组。** 汇总现有数据、实验、结果和本地轨迹中出现过的 2,517 个有效 task ID，另记录 3 个非运行时示例 ID。相同 ASIN、规范化同标题、仅数字不同的需求模板，以及近重复文本，按连通分量归组；历史成员的整个组均排除。
5. **先留出，再抽训练。** 近重复使用字符三元组 Jaccard：需求 ≥0.85、标题 ≥0.95；采用精确阈值匹配，而非概率 LSH。每组只选一个固定种子代表，先分测试、开发、验证，再分教师与 GRPO；剩余代表固定为训练备用。
6. **保留自然覆盖。** 按九个商品领域、标注需求项数量、预算是否明确、是否有指定规格联合分层，使用比例配额和最大余数分配。没有按模型成绩挑题，也没有人为凑简单/困难比例。

需求项计数包含功能、规格、显式品牌/型号和预算；≤4、5–8、≥9 分为三档。这是结构统计，不能当作模型实际难度，也不能把所有项都称为 Reward v3 硬约束。

## 质量审计

全库 23,421 题中，13,846 题通过本轮规则；排除历史重复组后剩 12,189 题，再选组内代表得到 12,077 题。

| 排除原因 | 涉及任务数 |
|---|---:|
| 价格提示未被预算规则解析 | 7,513 |
| 目标购买未得到有效 gold | 1,986 |
| 价格不可核验 | 695 |
| 规格不可解析或不可选 | 319 |
| 非成品/客服报价等规格 | 233 |
| 文本损坏 | 74 |
| 直接颜色冲突 | 32 |
| 零容量占位规格 | 24 |

原因可重叠，不能求和作为剔除总数；其中部分题可能语义合理，只是现有评分规则不能完整覆盖。

初版试采子集的文本抽查发现并形成规则的案例：2244 要棕色鞋但 gold 标银色；11547 的规格是“咨询客服报价”；20535 存在 `0kWh` 占位规格；20634 的指令含 `??` 损坏标记。这四题均已排除。抽查及规则不等于全库人工或模型语义认证。

教师候选与新测试均覆盖全部九个领域。教师候选三档需求项数量分布为 587 / 2,505 / 908；测试为 145 / 629 / 226，覆盖比例接近。各领域、预算和规格分布以 metadata 为准。

## 隔离、复现与使用

- 各主划分之间 task ID、重复组均零交集；与已记录历史任务及其重复组零交集。新训练和备用池与原 Final-200 零交集。原有数据与评测清单保留。
- `history.jsonl` 冻结历史用题及来源；`private/audit.jsonl.gz` 保存每题质量原因、重复组、分配结果和静态 gold 证据。私有审计只供检查，不作为 Actor 输入。源文件、运行时代码、配置、历史输入与成品文件均记录 SHA-256。
- 新版 `agent.py collect --role train` 自动强制使用 `held_out.jsonl`，其 4,713 题覆盖历史题、验证候选、开发、新测试及其整个重复组；`--role validation` 自动使用 `evaluation_holdout.jsonl`，保护其中 3,903 道历史/开发/测试相关题，同时允许采集验证候选。两者另行保护当前外层 Final-200，无需手工传留出参数；不能使用外层旧采集入口代替。

重新生成：

```bash
environments/ShopSimulator/.venv-shopsim/bin/python next/scripts/prepare_task_pool.py
```

默认复用已冻结的历史快照，不依赖旧 `outputs/` 文件仍在本地。`--refresh-history` 会重新盘点并重划分，不能在看过测试成绩后用它更换测试集。

验收包括成品数量/哈希、历史与跨集合隔离、严格 gold 条件、子集关系、精确近重复匹配与暴力枚举对照，以及独立目录完整重建。相关测试：[test_prepare_task_pool.py](../../tests/test_prepare_task_pool.py)。

**边界：** 本轮证明的是目标规格的静态可评分性及已定义重复规则下的隔离；未验证搜索策略成功率、全量语言标注一致性或真实模型难度。新测试按同来源分组留出，不能称为跨类别或跨环境泛化。后续采集记录真实验收率并审计训练题语义；测试不按教师或学生成功率筛选。
