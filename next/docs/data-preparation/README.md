# 阶段 1：任务准备与隔离

## 目的与方案

为教师采集、学生训练和独立评测提供固定任务。只读复用 ShopSimulator 原任务、商品和评分实现，检查目标购买可评分，排除明显标注问题；按商品及近重复需求分组，先隔离历史用题，再分层划分。未根据教师或学生成绩挑题。

## 已完成结果

23,421 个原任务中，13,846 个通过已定义的质量规则；排除历史重复组并选取组内代表后，固定 12,077 个独立任务。

| 用途 | 任务数 |
|---|---:|
| 教师采集及后续失败回流候选 | 4,000 |
| GRPO 训练候选 | 2,000 |
| SFT 验证采集候选 | 800 |
| 开发、选模 | 300 |
| 独立测试 | 1,000 |
| 训练扩量备用 | 3,977 |

教师试采 100 题、高频开发检查 50 题分别包含在教师候选和开发集中，不重复计数。

## 验收与使用边界

- 主划分之间、与已记录历史任务之间，task ID 和已定义重复组均无重叠；训练与外层 Final-200 无重叠。
- 配置、来源、历史用题、成品哈希与每题审计已保存，可从冻结快照重建。Actor 输入不包含静态 gold 审计。
- 测试不用于选模、调参、修复回流；SFT 验证候选即使采集失败也不能转为训练。
- 通过静态质量规则不等于全量语义认证；这是同来源的分组留出，不能称为跨环境泛化。

后续直接复用冻结划分。筛选规则、分布、命令和局限见[数据准备说明](methodology.md)；数量与哈希的权威记录见 [metadata.json](../../data/task_pool/metadata.json)。
