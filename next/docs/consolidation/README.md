# GRPO 后定向纠错与成功能力保留

**状态：实现与离线验证完成，尚未采集或训练。** 原终局 GRPO step500 继续作为主结果。本阶段是一次有对照的监督纠错实验，不把未执行的方案写成收益，也不把后续 SFT 收益归入 GRPO。

## 1. 为什么优先做这一版

| 已有证据 | 能说明什么 |
|---|---|
| Baseline test15/1,000 → S0 750/1,000；Astra教师809、Sol804 | 主要能力已由领域SFT学会，换教师不是当前最直接的补强；教师分数也不是学生理论上限 |
| S0 → 修复 SFT：dev 220→226，test 750→766；普通增量组 dev 218 | 定向纠错曾有价值，单纯增加示范未必有效 |
| 修复 SFT → 原终局 GRPO：dev 226→228，test 766→778；测试新增成功47、退化35，配对 p=0.2242 | 有净收益，但明显被退化抵消，尚未证明稳定提升 |
| 同一测试比较：循环52→24、错误购买12→26、平均步数10→8.498 | 策略更短、少循环，同时出现购买可靠性退化；不是所有能力全面改善 |
| S0直接GRPO：dev 220→226，test 750→759；仍低于原主结果 | 不优先继续降低起点来追求更大的相对增幅 |
| 局部信用最高dev225；稳定终局最高227；4×4最高225、最终224 | 现有实现没有超过原终局228，不继续堆batch、KL或分支估计 |

以上是现象，**不能唯一归因于灾难性遗忘、奖励设计或某个超参数**。稳定终局同时改了多项配置，也不能据此断言KL无用。优先检验两个直接问题：现有成功动作能否保住；失败状态能否获得真实可执行的正确续写。来源：[统一测试](../evaluation/results.md)、[S0对照](../grpo-s0/results.md)、[batch对照](../grpo-batch/results.md)、[探索备份](../project-completion-plan.md)。

## 2. 具体怎么做

| 环节 | 固定方案 | 目的 |
|---|---|---|
| 起点 | 原修复SFT基座＋原终局GRPO step500 LoRA，按既有模型清单逐文件校验；直接继续该adapter，重置优化器 | 与实际评测过的策略一致，不先BF16合并再新建LoRA |
| 学生采样 | 在既有、隔离的 **GRPO训练池2,000题**各执行一次，使用共享执行器与正式解码规则 | 获得当前模型真实访问的状态；不是复用旧S0失败冒充当前失败 |
| 教师接管 | 首次守卫拒绝、重复状态动作，或失败购买之前，按已有证据确定接管点；重新reset并执行前缀，逐次验证可见历史一致，再交给固定Astra | 纠正学生当前的决策；不要求教师logits，不给隐藏答案，不要求私有思维链 |
| 验收 | 只保留完整、可验证的`gold_purchase`；服务故障、不可验证结果、无法确定接管点或模板超长不入训练 | 用环境证据决定对错，不凭教师自评 |
| 数量 | 最多 **200条**唯一任务修复，最低 **100条**；不足则停止，不自动扩池或放宽标准 | 一次有界实验，避免低质量凑数；目标不等于承诺产量 |
| 成功回放 | 选同数量当前GRPO严格成功轨迹、同数量已有Astra成功示范，均按固定seed选择 | 分别锚定RL已有策略与原有任务能力 |
| 更新 | **修复∶学生成功∶原Astra示范=1∶1∶1**；修复仅监督教师后缀，失败前缀只作上下文；其余只监督assistant动作 | 给出明确正确动作，同时对成功行为提供保留约束 |
| 配方 | 原LoRA结构不变；LR **5e-6**、最多 **2 epoch**、有效batch **8**、双H100 BF16；每epoch保存并评测dev300 | 保守短程更新，最多150次更新；不重跑500步RL |

这是**单轮、学生状态驱动的监督纠错＋经验回放**，不是完整DAgger、OPSD或OPD，也不是新GRPO算法。学习率较旧修复SFT的2e-5降低4倍，是减少漂移的预设起点，**未经运行不能称为全局最优**。比例按样本数计算；沿用全局监督token均值loss，不能宣称三个来源各占1/3梯度或计算量。

沿用已有前缀回放/验收代码；不训练过程奖励模型、不新增偏好模型、不同时改环境、Reward v3、工具协议、KL和采样温度。当前保留/纠错信号通过监督loss提供，不改正式奖励。

## 3. 最小必要对照与验收

三种候选均保留：

1. **原GRPO不更新**：已有dev228/300，复用冻结证据。
2. **仅成功回放**：n条学生成功＋2n条原Astra示范。
3. **定向修复＋回放**：n条学生成功＋n条相同Astra示范＋n条教师修复。

两训练组从同一adapter独立开始，共享前两个锚定块、有效batch、更新次数、LR、seed和dev规则。监督token和实际GPU时间单列，**不是严格等token对照**；此对照检验“替换一块普通示范为当前失败纠正”是否值得，不单独证明回放或某种接管规则的因果贡献。

- 新候选必须 **dev严格成功数高于228，平均Reward v3不低于原起点**，否则保留原GRPO。合格者按成功数、较少丢失原成功题、平均奖励、较少动作、较早检查点排序。
- 每个候选报告新增成功、丢失成功、原成功保留率、错误购买、循环、平均步数、token与计算成本。净成功率变好不等于没有退化；不承诺所有指标同时提高。
- 若仅回放对照不差于修复组，则不能把收益归因于教师修复。不自动追加轮次或挑选测试失败题训练。
- 选模只用dev300；**本入口不运行test1000**。当前测试结果已多次被分析，后续同集结果只能称为既有基准复核；更强泛化结论需新的独立留出或预先固定的多种子验证。

方法依据：[DAgger](https://arxiv.org/abs/1011.0686)支持在学习者访问的状态上收集专家监督；[InstructGPT](https://arxiv.org/abs/2203.02155)使用辅助预训练梯度缓解能力退化。本方案借鉴这些原则，采用任务成功示范回放，并非论文方法的等价复现，其他任务上的收益不能直接外推。

## 4. 实现、执行与保留

- [冻结配置](../../configs/consolidation.json)；[数据/评测与选模](../../scripts/consolidation/workflow.py)；[后台执行入口](../../scripts/consolidation/run.py)。复用原回流模块和SFT trainer；只给trainer增加可校验的adapter续训入口，原SFT调用不变。
- 唯一运行目录：`outputs/consolidation/r1/`；`mine/`、`repair/`分别记录原始采样和教师usage；`dataset/`保存两组成品与监督token清单；`replay/`、`repair/sft/`保存训练与dev结果；`summary.json`汇总最终比较。正式阶段完成后将精简清单与总结提交`results/consolidation/r1/`，原始日志保留在outputs。
- 模型和检查点使用worker的`/tmp`工作目录，但保存时通过已有artifact队列等待开发机校验收妥，再异步上传HDFS；归档成功以回执为准。训练/评测均用未合并adapter，不自动导出合并模型。
- 沿用原双卡监控及空闲保活：运行计算时切换自适应负载，结束或可捕获异常时恢复两卡保活。不能保证worker被强制回收后继续运行；保活不能代替实时GPU/SM监控。

获得正式执行授权后，使用既有worker环境、凭证、备份接收器及HDFS上传器，设置`SHOP_ARTIFACT_QUEUE/ROOT`与`SHOP_KEEP_STATE/SHOP_IDLE_KEEP_ON/OFF`。模型根目录须包含冻结清单中的基座与原step500 adapter。后台启动形式：

```bash
nohup python next/scripts/consolidation/run.py \
  --models-root "$MODEL_ROOT" --work "$RUN_WORK" \
  --output "$RUN_OUTPUT" > "$RUN_OUTPUT/launcher.log" 2>&1 < /dev/null &
```

运行前创建独立`RUN_OUTPUT`目录；`RUN_WORK`位于artifact根目录内，日志目录使用开发机可见的共享存储。凭证不写入命令或仓库。初次检查后完整执行，不额外铺设小规模探查。

**本次验收：** 数据隔离、同预算组构造、小模型adapter输出等价与续训梯度、实际2B基座/adapter文件身份、完整dev选择、真实模板后缀mask、前缀回放及原SFT目标检查通过。详细离线检查见[验证清单](../../results/consolidation/r1/validation.json)。**没有执行正式采集、GPU训练或新增评测，效果待验证。**
