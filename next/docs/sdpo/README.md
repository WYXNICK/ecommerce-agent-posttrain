# SDPO：利用真实反馈的在线自蒸馏

**状态：实现与验证已完成，未启动训练。** 原终局 GRPO step500 仍是已完成的主结果，GRPO 后纠错 SFT 继续作为备选。

## 1. 目的与依据

目标是在已有较强 SFT 上，提高一次执行的可靠性，减少错误购买与循环。**以反馈能否帮助模型为优先，不为匹配 GRPO 而固定采样数量；统一评测口径仍保留。**

已有[固定模型诊断](../passk/results.md)：修复 SFT 的 dev 随机 pass@1 为 **69.29%**、pass@8 为 **88.33%**；原终局 GRPO 为 **74.83% / 89.33%**。不少任务能被采样做对，但选择不稳定，适合尝试从成功同题轨迹与实际失败反馈获得更细的监督。这个差距不是 SDPO 能兑现的收益预测，也不能证明 2B 自教师一定能理解反馈。

采用[SDPO 原论文](https://arxiv.org/abs/2601.20802)的反馈条件自教师与在线 logit 蒸馏；核对[官方实现](https://github.com/lasgroup/SDPO/tree/7c457fc1b1f636ae794eb0362ba37d4743b06fbc)，独立实现必要公式，不引入整套旧框架。多轮购物适配属于本项目扩展，不描述成原论文已有的购物实验。

## 2. 一条完整链路

```text
修复 SFT → 当前学生在训练池真实交互，每题采样 8 条
         → 同题严格成功示范＋可验证的执行反馈
         → EMA 自教师在各条学生轨迹的原状态上重新评分
         → 蒸馏同一批学生动作 token 的概率分布 → 更新学生
         → 每 50 步 dev300 选模 → 固定候选后再做最终评测
```

**起点：S-repair step72。** 它已经具有较好的总体成功率和规格约束能力，适合作为自教师的基础。新建 SDPO LoRA，从该 SFT 权重开始；不从 GRPO 权重续训，不重新采 Astra。学生与自教师都关闭 Thinking；正式 Astra 教师成品继续原样保留。

### 反馈怎么构造

| 情况 | 处理 |
|---|---|
| 同题有其他完整严格成功轨迹 | 使用其真实工具动作序列作为示范；成功必须满足完整 `gold_purchase`、`reward_valid=true` 等共享判定 |
| 本条有模型失败 | 加入实际终止状态、执行动作、守卫拒绝，以及计分器明确验证失败的预算/类别/偏好项；不猜测原因 |
| 本条严格成功 | 可参考另一条成功轨迹；禁止把本条自身当成功示范 |
| 全组奖励相等 | 有示范或真实失败反馈就可以学习，不套用 GRPO 的等分过滤 |
| 某条基础设施失败或不可验证 | 仅排除该条，不能当示范；其余有效轨迹仍可学习。SDPO 不计算组内奖励均值 |
| 没有反馈、反馈过长或教师上下文超限 | 对相应轨迹/动作显式 mask 并计数，不截断真实页面和动作目标 |

不读取隐藏目标商品 ID，也不从测试结果反推答案。反馈中允许使用训练环境已经返回的可验证约束信息；成功商品动作仅来自本批次实际执行成功的学生轨迹。

**多轮适配的关键：** 教师的额外信息放在初始任务之后，实际工具历史原样保留；明确要求以最后观察的当前页面为准，不能照搬另一轨迹中的页面按钮。学生执行时看不到回顾信息。每轮使用 vLLM 原始 prompt IDs、生成 IDs 和 logprobs；教师只换条件输入，对齐的目标仍是学生原来生成的同一批 token。历史观察、反馈文本及参考轨迹都不作为 SFT 标签。

### 学习目标

学生分布 `p` 不含事后反馈；教师分布 `q` 包含真实反馈和同一学生动作前缀：

```text
loss = 所有有效动作位置的 mean[ stopgrad(w) × KL(p || stopgrad(q)) ]
w = min(2, exp(学生采样 token 的 logp − vLLM 原始 logp))
教师 LoRA 参数 ← 0.99 × 旧教师参数 + 0.01 × 更新后的学生参数
```

- 使用论文富反馈配方的 **reverse KL、EMA 0.01、LR 1e-6**。这里对完整词表计算 KL，用 action-token 分块和重计算控制显存，避免 top-k 近似；不是只模仿一个教师生成答案。
- EMA 在 LoRA 参数空间维护，冻结的 SFT 基座共享；教师无梯度。先完成教师前向并恢复学生参数，再建学生计算图，保证 gradient checkpointing 回算正确。
- 每批只更新一次；对 vLLM 与训练内核的概率差异使用停止梯度的上限为 2 的重要性权重。不额外叠加 GRPO、SFT、长度奖励或参考策略 KL。
- Reward v3 用于验收、统计和正式评测；旧 `training_reward`（包括 −0.65）只保留作日志和有效性标识，**不进入 SDPO 优化目标**。SDPO loss 下降本身不等于成功率提升。

## 3. 本版配方与资源

权威配置：[sdpo.json](../../configs/sdpo.json)，未覆盖的运行参数复用 [grpo.json](../../configs/grpo.json)，最终配置完整写入每次 `run.json`。

| 项目 | 设置与原因 |
|---|---|
| 训练任务 | 冻结的 2,000 题在线池；保护验证/dev/test 与近重复组 |
| 每次更新 | 2 个有反馈任务，每题 8 条；每波 1×8、并发 8，增加同题成功示范机会；屏蔽条目后按实际有效 token 归一化 |
| 补采上限 | 每次最多 8 波；连续 10 次不足批次则失败退出，不无限重试 |
| 生成 | temperature=1、top_p=1、top_k=-1；显式禁用模型 generation_config 中隐含的截断；Non-thinking |
| 优化 | BF16 LoRA rank16/alpha32/dropout0，AdamW，LR1e-6，15步 warmup，grad norm≤1 |
| 训练预算 | 最多 500 次有效更新；正常完整结束，不按单次 dev 波动停训 |
| 学生预算 | 35 动作、24,576 上下文、每轮最多 512 生成 token，保持原执行协议 |
| 教师预算 | 最多 4,096 额外反馈 token、28,672 总上下文；不增加部署时预算 |
| GPU | 双 H100 同步 actor；按学生与教师上下文长度分配动作；沿用 FLA/SDPA、梯度重计算、vLLM 8 并发 |

选择 2×8 是为了提供更有用的 SDPO 反馈，不是因为已证明它是数学上的最优 batch。它与此前 4×4 GRPO 的组内均值奖励训练机制不同，不能直接套用那次负结果。新增成本主要是更多采样和每个动作一次教师前向；实际时间以首次完整训练的吞吐为准。

加速限定在计算实现：双卡分摊动作、共享冻结基座、FLA/SDPA 与分块重计算；不缩短轨迹、删减反馈或用低精度量化替换模型。分别记录采样耗时、更新时间和有效动作 token 吞吐，保活产生的利用率不计作训练效率。500步是本轮初始预算，不代表已经验证的最优训练长度。

## 4. 如何判断是否发挥作用

1. **信号有效：** 记录示范/环境反馈覆盖、成功与失败有效轨迹、被屏蔽动作、生成与接收 token、教师相对学生的采样 token 概率差。后者用于排查，不把失败轨迹所有动作都视为错误，也不作为提升证明。
2. **训练稳定：** 监控蒸馏 KL、entropy、梯度范数、采样/训练概率差、GPU显存与耗时。数值异常、服务失败或无有效训练批次时停止并保留日志。
3. **任务实际改善：** 每50步 dev300；以严格成功数、Reward v3、较少动作、较早步数选模，起点也参与；逐题记录新增成功与退步，以及错误购买、循环。不能只看训练 reward。
4. **最终确认：** 固定候选后，与 S-repair、原终局 GRPO 对照 test1000，并对选中候选复用既有 pass@1/8 诊断。测试已多次用于报告，不能包装成全新盲测；没有提升就保留原主结果。

目标是同时改善任务成功率与稳定性，不预设必须涨若干百分点。原论文也指出弱模型可能无法有效利用反馈；本项目尚需实验证明 2B 自教师的指导能转化为未见任务的收益。为了控制实现规模，本版不引入外部教师、思考模式切换、混合算法或额外奖励网络。

## 5. 验收结果

见[验收清单](../../results/sdpo/validation.json)：新增10项 SDPO 检查通过，相关测试集共50次测试执行通过；覆盖反馈来源、因果 token 对齐、完整 KL 数值/梯度、跨卡归一化、EMA 恢复与续训。

双 H100 的一次真实批次完成16条轨迹、2,736个动作 token 的教师前向和双卡反向传播，**优化器更新0次**。蒸馏 loss 为0.03087，梯度范数0.50985，采样/训练平均绝对 log 概率差0.000925，重要性权重裁剪比例0。该批次核心计算约70.38秒，actor 进程峰值分配约7.30/7.24GiB（不含独立 vLLM 服务）。

这证明链路、梯度和该批次显存可用，不能据此证明成功率提升、最长上下文显存上限或完整训练时长。源码、配置、原始轨迹及验收日志均已校验备份到开发机和 HDFS；退出后双卡保活已恢复。

## 6. 实现、执行与产物

复用共享入口 `scripts/grpo/launch.sh --variant sdpo`；独立逻辑在 [self_distillation.py](../../scripts/grpo/self_distillation.py)。目录名 `grpo` 是已有在线训练基础设施，SDPO 的结果独立保存：

- 正式运行：`outputs/sdpo/r1/`；总结：`results/sdpo/r1/`；文档：本目录。
- 验收：`outputs/sdpo/validation/`；检查清单与结果：`results/sdpo/validation.json`。
- 保留配置/源码、原始轨迹、反馈来源与原文、训练/评测日志、TensorBoard、LoRA＋优化器＋EMA＋随机状态。每50步先校验备份到开发机，再排队归档 HDFS。
- 正常结束或可捕获失败恢复双卡保活。worker 强制回收不能靠进程内清理恢复，须依靠已落盘备份。

在已设置 `SHOP_RUNTIME`、`SHOP_GRPO_KERNELS`、归档队列与保活脚本环境变量后：

```bash
# 一次真实批次验收：采样、教师前向和双卡 backward，禁止 optimizer.step/导出/正式评测。
bash next/scripts/grpo/launch.sh --variant sdpo --validate-only \
  --model "$REPAIR_SFT" --work "$SDPO_CHECK_WORK" --output "$SDPO_CHECK_OUTPUT"

# 获得正式执行授权后，在独立目录启动；不覆盖验收目录。
nohup setsid bash next/scripts/grpo/launch.sh --variant sdpo \
  --model "$REPAIR_SFT" --work "$SDPO_WORK" --output "$SDPO_OUTPUT" \
  > "$SDPO_LAUNCHER_LOG" 2>&1 < /dev/null &
```

训练入口自动完成 dev300 选模、归档及选中/最终模型导出；测试和 pass@k 不在这条命令中自动执行。以已评测的 **SFT 基座＋LoRA** 为权威模型，BF16 合并副本只作方便使用的导出。
