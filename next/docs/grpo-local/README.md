# 局部信用 GRPO（R-local）

## 1. 目的与当前状态

**正式训练运行中。** 检验：在终局奖励之外，为少量动作提供局部回报差，是否值得额外采样成本。

已有 test1000：S-repair 76.6%，终局 GRPO step400 / 500 为 77.0% / 77.8%。step500 的循环和平均步数减少，但错误购买由12增至26；相对 S-repair 的逐题配对检验 p=0.2242，尚不能宣称稳定提升。见[冻结对照](../evaluation/results.md)。这些现象支持继续检验训练信号，**不直接证明信用分配是瓶颈**。

从同一个 **S-repair step72** 独立开始，不接着 step400/500 训练。数据、奖励、动态采样、LoRA、优化器、500次更新及每50步 dev300 选模继承[终局配方](../../configs/grpo.json)；仅增加[局部配置](../../configs/grpo_local.json)。

## 2. 同状态、同策略的动作比较

1. 先按原流程筛出终局回报有差异的训练组。约 **10% 的入选轨迹**参与比较，每条均匀选一个可完整回放的决策点，不根据成功/失败标签挑点。
2. 记录动作前的真实历史和 token 上限。从**当前更新前的同一学生策略**再采一个候选动作；与原动作相同则跳过，不反复抽到满意为止，不用教师或正确答案指定动作。
3. 固定原动作、候选动作，各 **8次续跑**。每次 reset 相同任务并重执行原前缀，核对原始决策状态、可见历史和剩余 token 预算。仅规范化租约字段，并排除源码已确认不被当前 actor/奖励使用的可选 persona 缓存元数据；任务、商品和奖励状态仍须一致。两动作的同号续跑使用配对种子，但不同前缀不保证相同生成。
4. 分支均由同一更新前学生继续执行，共享原 `run_episode`、守卫、工具、观察、步数和终止规则。前缀预算不重置；不同动作后按实际消耗继续扣预算。
5. 分别用8次终局 `training_reward` 的均值估计 Q，只给**原训练轨迹被选中动作的 assistant token**增加优势。分支不进优化器，不替换主轨迹 token 或旧 logprob。

```text
A_episode  = 原终局 training_reward − 同题组内均值
A_local    = (mean(return_original) − mean(return_alternative)) / 2
A_selected = A_episode + 0.5 × clip(A_local, −0.5, 0.5)
```

其余动作仍用 `A_episode`；观察与历史不参与 loss，双卡仍按主轨迹动作 token 总数归一化。增量绝对值最多 **0.25**，用于限制噪声影响，不声称超参最优。`weight=0` 时无分支采样、无增量，退回终局目标。

**失败与噪声：** 可验证终局用 Reward v3，模型非终局失败仍为−0.65。16次续跑必须全部可比较；任一次回放漂移、基础设施故障或奖励不可验证，则不使用整对估值，原轨迹仍按终局规则学习。不挑成功子集计算 Q，不跨策略版本复用 Q。无法解码的响应仍接受终局训练，但不做局部干预；等分组筛选不变。

记录逐分支回报、方差、配对标准误、有效配对率、非零增量、请求和输入/输出 token、耗时。**这是有噪声的辅助局部优势，不是无偏优势估计或严格因果证明**；裁剪不消除误差，也不保证提升。

## 3. 验收与对照

已完成的链路验收使用每动作4次续跑，原记录保持不变（[机器可读汇总](../../results/grpo/local/validation.json)）：

| 检查 | 结果 |
|---|---|
| 离线行为与梯度检查 | **47项通过**；冻结执行指纹不变 |
| 真实决策 / 分支 | **64个决策点，来自16个训练任务；248条分支** |
| 状态与预算回放 | **248/248一致**；原始记录独立复核通过 |
| 动作比较 | **30组有效，33组同动作跳过，1组奖励不可验证弃用**；无基础设施失败 |
| 局部信号 | **24组非零：15正、9负**；其余6组有效但差值为0 |
| 估值噪声 | 原始局部优势的配对标准误中位数 **0.195**；不能视为已收敛的 Q |
| 分支成本 | 2,050次模型请求、24,538,996输入 / 50,325输出 token；含候选动作，不含主采样；验收采样总耗时约 **13.8分钟** |
| 权重与运行收尾 | **0次参数更新**；两卡保活自动恢复，源码与完整日志已校验备份至开发机及 HDFS |

结论：**链路及信号存在性通过，具备进入受控训练实验的条件；尚未证明训练收益。** 按本次小样本比例，10%抽样约对应 **3.75%的轨迹产生非零增量**，并非10%；仅16个任务，不能把这一比例当作全训练池的精确估计。正式训练将每动作续跑由4次提高至8次：验收的24个非零比较中，13个的信号绝对值不超过配对标准误，支持增加固定采样数。并发仍为8，不增加模型副本或并发显存；保留10%抽样、原权重与裁剪，避免同时改动多个训练超参。增加采样只能降低部分估计噪声，不能保证收益。

- 离线检查：状态与预算回放、真实续跑、失败分类、λ=0、动作定位、全局 token 梯度归一化、冻结执行协议不变。
- 一次真实验收：只用隔离的 GRPO 训练池，**64个决策点、最多512条分支**。重复动作或不可用候选减少实际分支数；不更新权重、不跑开发集/测试集。链路通过、存在非零信号都不能证明训练有效。
- 正式训练已获授权：从 S-repair 独立运行500次更新，每50步保存、备份并评测 dev300；严格成功优先，再比较原始奖励、动作数及较早检查点，起点 SFT 也参与选模。**不因一次开发集波动提前停训**；数值异常、服务故障或持续无有效组才失败退出并恢复保活。
- 验收收益同时看严格成功、原始奖励、错误购买、循环和动作数；分支信号、采样成本不能冒充任务改善。500步是本轮预算，追加预算或多种子另行决定。
- **R-budget 与多种子尚未实施**：根据实际分支和训练成本补终局 GRPO 的相当计算预算对照，才能区分信用分配与更多计算的收益。
- 六模型 test1000 已看过，本轮不读它选点或调参；后续同集成绩须披露重复使用。独立确认新方法需另预注册未看过的留出集。

## 4. 入口与证据

在已配置运行环境、归档队列和 GPU 保活变量的 worker 中执行：

```bash
# 真实分支验收：无 optimizer update 或模型合并
bash next/scripts/grpo/launch.sh --variant local --validate-only \
  --model "$S_REPAIR_MODEL" --work "$VALIDATION_WORK" --output "$VALIDATION_OUTPUT"

# 正式训练：已获执行授权，使用独立工作/输出目录
bash next/scripts/grpo/launch.sh --variant local \
  --model "$S_REPAIR_MODEL" --work "$LOCAL_WORK" --output "$LOCAL_OUTPUT"
```

复用双卡 FLA/vLLM、开发机校验备份、HDFS 异步归档与退出保活。分支最多8路，与主采样分阶段执行；不增加教师、critic 或学生模型副本。保活负载不计为训练效率。

## 5. 方法依据

[RTMC](https://arxiv.org/abs/2604.11037) 用共享状态的续跑回报估计步骤价值；本实现借鉴 Monte Carlo 思路，采用显式回放比较两个动作，**不是论文的完整复现**。[多轮细粒度信用分配研究](https://arxiv.org/abs/2505.11821) 讨论终局与逐轮信号的差异，其其他任务上的收益不能直接外推到本购物环境。因此保留终局、成本与统一评测对照。
