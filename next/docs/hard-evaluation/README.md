# Hard Set：选择标准与候选审计

## 目的与定位

补充回答：**在存在多项选择、预算联动和相似商品干扰的任务上，SFT、数据修复和 GRPO 分别有什么收益？** 原 test1000 继续作为主结果；Hard Set 单独报告，不替换主测试，也不混合计算总分。

当前最适合的是**模型成绩无关的结构型 Hard Set**。本页的阈值是预先固定的可解释规则，不是已证明的最优数值；通过规则的任务先称为候选，完成语义与交互验收后才能成为正式测试集。不承诺 GRPO 必然在其中提升。

### 为什么不能直接按“约束多”选题

现有 test1000 的结果如下，分层只作诊断，不用于挑选新题：

| 标注需求项数量 | 题数 | S0 成功率 | R-outcome step500 成功率 |
|---|---:|---:|---:|
| ≤4 | 145 | 64.14% | 68.97% |
| 5–8 | 629 | 75.52% | 78.38% |
| ≥9 | 226 | 80.53% | 81.86% |

需求项越多并未越难，详细描述反而可能更容易定位商品。因此不使用“约束≥9”“文本很长”“模型走了很多步”“SFT 失败、GRPO 成功”等条件定义 Hard。证据：[测试汇总](../../results/evaluation/s0-grpo-test/summary.json)、[冻结任务审计](../../data/task_pool/private/audit.jsonl.gz)。

## 1. 先过质量与隔离门槛

- **按参评模型隔离：** 只从冻结备用池选择，保护最终参评模型的训练、修复回流、验证和开发数据及重复组，不从 dev300、test1000 挪题。仅被已排除的普通增量 SFT 使用的任务可以纳入；其模型及后续派生模型不能在这套 Hard Set 上作为无泄漏对照。候选名单尚不改变冻结训练划分；正式使用前必须加入训练留出保护。
- **能评分：** 标注商品、规格存在且可选择，价格为正且能确定；离线目标购买必须得到 `gold_purchase`、`reward_valid=true`。复用 Environment v2.1 / Reward v3，不改奖励使任务通过。
- **不是数据问题造成的难：** 排除明确的颜色冲突、损坏文本、订金/补差/客服报价、零容量占位、随机目标规格等。规则无法判断的语义冲突不能自动放行成正式测试题。
- **有可核对的检索证据：** 本版用原始公开需求作为固定查询，目标出现在前 20 名。未满足者进入额外检索审查范围，不等于无解；查询不添加隐藏 ASIN、标题或答案。

## 2. Hard：至少同时满足以下两类难点

| 难点 | 可执行标准 | 检验什么、为什么这样设 |
|---|---|---|
| **A 多规格选择** | 至少 2 个任务明确要求的规格轴，每轴至少有 2 个真实可选值 | 要同时保持多项需求；只有一个按钮可点不算选择困难。不把各轴乘积声称为已验证的可售组合数 |
| **B 规格与预算联动** | 有可解析且不含近似表述的预算；gold 规格在预算内，保持其他选择不变，改变某个必选规格能得到价格可确定且超预算的真实变体 | 检验选规格后是否重新核价；仅出现“预算”二字或所有变体同价不算 |
| **C 相似商品辨别** | 固定查询前 20 名内，至少 3 个排在目标前的同类商品，在存在的规格轴上缺少任务指定值 | 检验是否核查规格而非直接选搜索首项。缺轴/缺元数据属于不可验证，不能冒充规格冲突 |

即 `A+B`、`A+C`、`B+C` 或三者同时满足。至少两类可避免把一次简单选色或普通搜索包装为 Hard；C 的“三个”表示多候选干扰，前 20 对齐环境的一页商品窗口。A/B/C 是不同侧面的难度信号，**不声称统计独立或足以保证模型低成功率**。

C 是检索与规格核查的代理指标：不证明模型必须打开三个商品，也不证明竞争商品必定不满足用户的真实意图；规格同义词、可接受替代品仍须语义审查。完整需求查询只用于固定离线探针，实际 Agent 仍应遵守工具描述，生成简洁查询。静态 gold 校验同样不能证明用户需求与隐藏答案完全一致。

## 3. 本轮数量与产物

**使用范围：** 按用户确定的最终候选，普通增量 SFT 不参评。核对发现，179 道已采集备用题仅出现在其采集记录中，包含 144 条接受示范和 35 次未接受尝试；它们与修复组训练、验证、共同回放及冻结的教师训练/验证、GRPO、开发和测试池均无任务组交集。两组增量 SFT 从同一 S0 独立开始，普通组的数据不会通过权重流入修复组。因此这 179 题恢复筛选资格，难度及质量标准保持不变。

这批题不是“整个项目从未接触”的数据，但对当前参评模型保持训练隔离；候选证据保留来源标签，不根据普通组或教师的执行成功与否筛选。若一题同时出现在任何其他使用来源，仍排除，而非整体忽略暴露记录。

2026-11-09 全量离线审计与逐题文本初审结果：

| 环节 | 数量 | 含义 |
|---|---:|---|
| 冻结备用池 | 3,977 | 不是全部未使用 |
| 仅在普通增量分支接触、恢复资格 | 179 | 144 条接受示范与 35 次未接受尝试，均重新按相同规则筛选 |
| 整个项目未接触的独立任务 | 3,798 | 按保留的本地实际记录审计，不把计划采集 ID 当作已用 |
| 对当前参评模型符合隔离要求的待筛池 | **3,977** | 3,798＋179，不包含普通增量 SFT 及其派生模型 |
| 本版确定规格/正价格门槛排除 | 12 | 3 道零价，9 道随机或非标准目标；不等于全部属于源数据错误 |
| 目标未进入固定查询前 20 | 405 | 暂不纳入本版，若后续扩充需单独做检索审查 |
| 命中至少两类难点 | **117** | 结构候选，覆盖全部九个领域 |
| 文本初审明确排除 / 隔离待核 | **6 / 6** | 与模型分数无关的语义、规格或交付问题 |
| 初审后可继续验收的候选 | **105** | 仍需完整语义复核与真实交互验收 |

117 道结构候选中：A+B 为 41，A+C 为 12，B+C 为 61，A+B+C 为 3；四类互斥。A/B/C 单项命中数不是可以直接相加的 Hard 数量。当前**没有完成正式交互认证的 Hard 测试集**，不能把 105 宣称为已验证的困难题总量；标准外也可能存在真正难题。

恢复的 179 题新增 4 道结构候选（1152、5997、7289、12240），文本初审未发现需要新增排除的明确矛盾，仍待正式验收。因此可继续验收数量由 101 增至 **105**，不是直接增加 179 道 Hard 题。

初审发现的代表问题：

- **776：** 需求为 2.8×2.8×2.2 cm，gold 为 280×280×220 mm，尺寸相差十倍。
- **7402：** 需求同时要求黑色和银色，gold 只要求黑色。
- **22534：** 用户未给儿童身高，gold 却限定 110；商品还有其他六个身高选项，隐藏评分要求无法从需求推出。
- **6266：** 用户要三轮摆摊车，gold 是车架/台面/顶棚组合，是否包含完整车体不明确，隔离待核。

逐题初审是 Assistant 对需求、标题和 gold 规格的文本审读，部分疑点回查原始选项，**不是人工专家认证或强模型真实执行**；其余候选的功能、材质、竞争商品同义词等仍需复核。所有排除/隔离理由见 [review.json](../../results/evaluation/hard-candidates/review.json)，统计与哈希见 [summary.json](../../results/evaluation/hard-candidates/summary.json)，后续验收名单见 [candidates.jsonl](../../results/evaluation/hard-candidates/candidates.jsonl)。

## 4. 如何形成正式测试与报告结果

1. **审题并保留理由：** 检查候选的需求、商品说明、规格与价格是否一致，特别关注同义词、隐含要求和可接受替代品。强模型可协助审题，但有争议的题需人工裁决；不能按谁能答对来决定保留。
2. **验收一条可执行成功路径：** 从公开观察搜索、浏览、选择到购买，保证共享守卫允许执行，终局严格成功。教师第一次失败不能自动淘汰任务；先区分策略失败与题目问题。修正数据/评分语义属于另一个版本，不能暗中修题混入本版。
3. **冻结后统一评测：** 固定 ID、重复组、版本、排除理由和哈希，加入训练留出保护，再使用同样预算与执行协议比较 Astra、S0、S-repair、R-outcome 及当前 batch 对照的开发集选定模型。全体模型失败也保留；不看结果再删题。
4. **同时报告主集与 Hard：** 严格成功率、Reward v3、错误购买/规格/预算失败、步数与 token 成本，以及相对 SFT 的逐题配对差异和置信区间。题数少时明确统计能力限制，不将不显著的小幅差异包装成稳定收益。

质量优先，不为凑 300 题放宽标准。若候选不足，使用实际验收数量作为挑战子集；105 题中每题约占 0.95 个百分点，小幅差异仍可能落在统计波动内。若明显过多，提前按领域与难点组合分层抽样。当前没有必要额外拆 Hard-dev：本轮只比较已有模型；将来若据此设计训练，另建 Hard-dev，本套继续留作测试。

如完整评测后发现该集合不比主集更难，应如实称为“复杂约束挑战集”，保留结果，不按模型表现重新挑选。这样的补充能增强项目的诊断能力，但不能单独证明新的算法收益。

## 复现与边界

配置：[hard_candidates.json](../../configs/hard_candidates.json)；实现：[audit_hard.py](../../scripts/evaluation/audit_hard.py)。在仓库根目录使用项目环境运行：

```bash
python next/scripts/evaluation/audit_hard.py
```

此命令只进行 CPU 离线审计，不调用教师、启动 GPU 评测或改变训练任务。它输出结构候选；文本初审是独立步骤，最终候选等于结构候选减去 `review.json` 中的排除/隔离 ID。全量逐题证据与实际接触记录保存在 `next/outputs/evaluation/hard-candidates/`；精简结果及 117 道结构候选的压缩证据位于 `next/results/evaluation/hard-candidates/`。候选任务清单只含 ID；`private-evidence.jsonl.gz` 含 gold 与审计依据，仅供审核，不能作为 Agent 输入。

必要检查覆盖价格冲突、非成品选项、元数据缺失与真实规格冲突的区别，以及接触过同组任务时的隔离；5 项检查通过。原数据划分、训练/评测代码和正在运行的任务保持不变。后续新训练若使用备用池或参评模型集合改变，必须重新核对数据血缘，不能直接复用旧的隔离结论。
