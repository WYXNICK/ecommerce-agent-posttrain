# 四个固定模型的多次采样诊断

**Pass@k 诊断状态：已完成。** 本阶段是当前优先诊断；原终局 GRPO step500 仍是主结果，GRPO 后纠错 SFT 仅为备选。

## 目的

区分两种现象：模型能采到正确购物轨迹，但单次成功概率不足；或在给定采样预算下仍难以找到正确轨迹。检查 SFT 修复和 GRPO 是否提高单次可靠性、改变成功覆盖面，以及改善是否被其他任务退化抵消。不预设结果支持继续 SFT 或 RL。

## 固定设计

| 项目 | 设置 |
|---|---|
| 四个模型 | S0 step750、修复 SFT step72、S0→GRPO step450、修复 SFT→原终局 GRPO step500 |
| 身份 | 复用原评测清单的基座与未合并 adapter，逐文件校验 SHA256；不重新合并模型 |
| 任务 | 冻结完整 dev300；每模型每题独立执行8次，共9,600条有效执行记录 |
| 解码 | temperature=1、top_p=1；vLLM默认生成配置，不继承模型目录中的 top_k 等采样默认值；关闭thinking |
| 随机性 | 固定总seed，按任务、采样轮次、对话轮次派生请求seed；同一任务同一采样轮次的基础设施重试沿用seed。并发GPU执行不承诺位级可复现 |
| 环境 | 每条轨迹独立reset；沿用 Environment v2.1、Reward v3、Action Guard、观察、工具及预算；不同尝试不共享反馈 |
| 成功 | 沿用既有严格成功函数：完整可验证gold_purchase，reward_valid=true及终局完成等条件全部满足 |
| 失败 | 模型失败计入分母且不重采。仅重试未完成/基础设施失败；最多3轮补齐，仍有缺失则中止正式汇总，不输出选择性成功率 |
| 执行 | 两卡各运行一个模型服务，每模型8路并发；两轮覆盖四模型。无训练、教师API或test1000调用 |

唯一参数及身份引用入口：[冻结配置](../../configs/passk.json)。贪心参考复用原dev结果，温度0与随机采样结果分栏报告，不混算gap。

## 指标与比较

每题有8次尝试、成功次数为c，计算 `pass@k = mean[1 − C(8−c,k)/C(8,k)]`，k为1、2、4、8；当8−c<k时该题估计为1。pass@1使用全部8次的成功比例；pass@8为至少成功一次的任务比例。[估计方法](https://arxiv.org/abs/2107.03374)

- 每模型：pass@1/2/4/8、95%任务bootstrap区间、0/8到8/8任务分布、平均Reward v3、步骤和token用量。
- 三个预设配对：S0→修复SFT、S0→S0-GRPO、修复SFT→原终局GRPO；报告Δpass@k及区间、观察到的覆盖新增/丢失、成功次数转移矩阵。
- 按300道任务成组重采样10,000次，配对模型共用任务索引。不能把2,400条轨迹当作2,400道独立题；区间不覆盖多训练种子不确定性，未作多重比较校正。

## 如何据此决策

| 现象 | 可以支持的判断 |
|---|---|
| pass@1提高、pass@8接近 | 与更有效利用现有成功轨迹的解释一致 |
| 两者都提高 | 相同预算下单次可靠性和成功覆盖面均改善 |
| pass@1提高、pass@8下降 | 检查是否存在默认表现与成功覆盖面的权衡 |
| 两者都下降 | 优先检查更新、奖励及退化原因，避免继续扩大训练 |
| 失败题大量0/8 | 支持进一步检查教师纠正价值，不能断言模型完全不会 |

有限8次采样下的覆盖变化不等于已证明能力获得/遗忘。pass@8使用事后成功判定，不代表实际部署可安全重试或能选中成功轨迹。dev已用于选模，本诊断用于开发决策，不作为新的独立测试结论；dev轨迹禁止回流训练。

## 结果与复盘入口

已完成9,600次执行，见[结果与分析](results.md)。原终局GRPO相对修复SFT：随机pass@1提高5.54个百分点，pass@8提高1.00个百分点；前者配对区间不跨0，后者仍跨0。完整计数、区间及证据见[结果清单](../../results/passk/dev300/summary.json)，归档全部完成。

原始证据按 `next/outputs/passk/dev300/<模型>/replicate-00…07/` 保存，含run清单、逐条轨迹和汇总；根目录status.json与各模型日志用于查看进度。每模型完成后备份开发机/tmp，再由既有队列归档HDFS；最终日志另存完整证据。正常完成或可捕获中断后恢复双卡保活。

实现：[采样与统计](../../scripts/passk/diagnose.py)、[后台执行](../../scripts/passk/run.py)。关键验收覆盖组合估计、任务配对区间、随机种子、仅基础设施重试、严格终局成功及模型身份。
