# S0 直接终局奖励 GRPO（R-s0）

**状态：训练与开发集选模已完成。** 见[结果](results.md)。 原终局GRPO step500继续作为已验证的可用主结果。本实验只检验RL起点，不预设更大涨幅或更高最终成功率。

## 目的与方法

对比 **S0 → GRPO** 与已有 **S-repair → GRPO**，判断失败修复SFT是否是更好的RL起点。复用已验收的S0 step750（dev220/300），不重跑教师采集和SFT；新建RL adapter与优化器。

| 项目 | 固定设置 |
|---|---|
| 配方 | [原终局配置](../../configs/grpo.json)＋[S0身份覆盖](../../configs/grpo_s0.json)，仅version与基座权重SHA256不同 |
| 数据 | 同一冻结GRPO训练池2000题，与所有留出隔离 |
| 采样与更新 | 每次2个有效任务×每题4条；8路采样，temperature/top_p=1/1；最多8批补采 |
| 训练信号 | Reward v3；非终局模型失败−0.65；基础设施/不可验证过滤整组；等分组过滤；组内均值中心化，不除标准差 |
| 优化 | 双卡BF16 LoRA r16/alpha32，LR1e−6，15步预热，clip .2；全局动作token均值；KL=0，无局部/长度奖励 |
| 预算 | 500次有效更新，共4000条进入优化的轨迹；实际生成量、token和耗时另计 |
| 选模 | 每50步完整dev300；含S0起点，按严格成功数→Reward→较少步骤→较早步数选优 |
| 停止 | 正常完整500步；异常沿用有界补采、服务与数值检查，不按一次开发集波动提前停止 |

模型加载前核对S0权重哈希，起点评测从S0权威总结读取，禁止复用S-repair成绩或优化器状态。首批正式更新检查采样/训练logprob、有限梯度及显存，不增加多轮小规模训练。恢复检查点时核对完整训练配置，防止串用其他实验状态。

## 运行与保存

复用 `scripts/grpo/launch.sh --variant s0 --model "$S0_MODEL" --work "$GRPO_WORK" --output "$GRPO_OUTPUT"`。沿用冻结运行环境、FLA算子、共享执行器和双卡负载分配；路径通过启动环境提供，不另建训练框架。

- **日志入口：** `outputs/grpo/s0/status.json`、`progress.json`、`train.log`；原生TensorBoard写入该目录的`tensorboard/`，开发机6016端口的`R-s0`分组实时展示。
- **原始证据：** `run.json`记录模型、数据、配置和源码指纹；`metrics.jsonl`记录更新与采样成本；`rollouts/`保留生成轨迹，`dev/step-*/`保留各检查点评测及逐题得失。
- **保存：** 每50步将adapter、优化器、随机状态、任务顺序与日志校验复制至开发机`/tmp`；独立队列异步归档HDFS，配额失败保留本地并重试。最终导出选中与最后模型；评测身份仍以精确基座＋adapter为准。
- **后台：** supervisor与SSH会话分离；结束或可捕获失败后恢复两卡保活。执行期间自适应填充不计作训练吞吐，worker被回收不能依靠进程恢复。
- **结果：** 完成后生成本目录`results.md`与`results/grpo/s0/summary.json`并更新总计划。原终局及探索备份不会被覆盖。

## 启动验收

29项CPU契约检查通过；S0权重哈希、首批双卡有效更新、采样/训练概率一致性和有限梯度已核验，源码快照已备份开发机及HDFS。见[验收清单](../../results/grpo/s0/execution.json)。这些检查证明执行链路正常，不代表成功率已提升；训练结果按dev300选模后汇总。

## 结果判断

同时报告相对S0的增益与相对已有GRPO的绝对表现，包含成功率、奖励、错误购买、循环及成本。起点更低导致的涨幅更大，不等于最终模型更好。单种子对照不证明稳定性；当前自动任务仅包括训练和dev300选模，最终测试候选另行冻结。batch和每题采样数实验只列入[总计划](../project-completion-plan.md)，本轮不自动启动。
