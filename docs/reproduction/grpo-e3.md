# GRPO E3：学习可确认的规格遗漏购买失败

> 历史200题实验记录；本页选模与“主结果”仅适用于该历史系列。当前项目结论见[核心结果](../results.md)。

E3 以 E1 已执行源码和原 Chat 评测协议为基线，只改变一类失败样本的训练处理。
E1 的 138/200 主结果及 E2 补充结果保持不变。E2 的预算、原始 token 历史和
工具配置修改从本轮执行入口撤回；其实现保存在提交 `8bec919` 与 E2 冻结源码中。
本轮已完成，E3 为 131/200，同协议 E1 重评为 138/200；完整结论与保留边界见
[E3 补充实验结果](grpo-e3-results.md)。

## 实验变量

当环境给出正常、完整的 Reward v3 终局，但购买不可验证，且价格解析方法明确为
`effective_price_axis_unselected`，说明模型未选择唯一影响价格的规格轴。
环境解析器只有在该轴存在至少两个已知不同价格、而该轴未选择时才返回此方法。
E3 将该轨迹标为模型失败，使用 E1 既有 `model_failure_reward=-0.65` 作为训练成本，
不再仅因 `reward_unverifiable` 丢掉所在采样组。

其他不可验证原因（多价格轴、已选规格价格缺失、未知原因）继续过滤；环境服务、
投影与协议故障继续过滤。仅保存价格解析方法，不把原始私有计分证据送入 Actor。
`learn_unverifiable_purchase=false` 可关闭新增处理，恢复 E1 奖励与筛组语义。

环境 `reward_valid=false`、`reward_type=reward_unverifiable`、原始 Reward v3 分数
和验证选点分数保持原样；严格成功仍须完整有效的 `gold_purchase` 终局。
训练奖励是筛组与优势计算的共同依据，环境有效性与训练资格分别记录。
新增原生指标 `trajectory/model_unverifiable_purchase_rate` 与逐轨迹诊断用于确认
新失败样本实际进入更新，而不只是在生成阶段出现。

## 问题核验

E1 生成日志有 518 条奖励不可验证轨迹，实际更新中为 0 条。旧日志未保存具体
价格解析原因；回放每个不同训练任务的第一条已保存失败轨迹，共 105 条：
74 条为 `effective_price_axis_unselected`，31 条为 `multiple_effective_price_axes`。
这不是全部 518 条轨迹的分类统计；回放未调用模型、未使用 Final-200。

实际 Worker 上 115 项相关回归通过，包括真实工具执行与 Chat 入口动作一致性、
环境无效标记保留、训练/验证奖励分离、可训练失败 group 保留及真实 veRL 优势方向。
正常子任务失败与监督进程 SIGKILL 的清理/双卡保活恢复均已验证。

## 固定条件与执行

从与 E1 相同的 SFT 合并权重新建 LoRA，不承接 E1/E2 参数，不重新运行 SFT。
E1 的模型生成、工具模板、守卫、观测预算和原 Chat 评测代码保持一致。
相同 1000/50/200 任务划分、2×H100 80GB、LoRA rank 16 / alpha 32、学习率 1e-6、
每批 2 题 × 每题 4 条轨迹、无 KL、无长度 shaping、500 次实际更新；每 10 步保存、
每 50 步验证。按验证平均原始 Reward v3 选点，同分取较早步数。

本轮输出为 `outputs/reproduction/grpo-e3-20261008/`：

- `status.json`：执行阶段与完成状态。
- `train.log`、`training_diagnostics.jsonl`：原生训练输出和采样/更新证据。
- `tensorboard/`：原生 logger 事件，不补造训练曲线。
- `checkpoint-selection.json`：验证选点；Final-200 不参与。
- `evaluation/e3/`、`evaluation/e1/`：原协议下的新模型和同一 E1 checkpoint 的重评。
- `evaluation/results.json`：精确汇总与配对得失；历史 E1 主结果单独保留。
- `run_manifest.json`：源码、数据、模型与执行核验。

源码冻结后在后台独立会话执行；GPU 模型与全部检查点放 Worker 数据盘。
训练期低占空比保活独立于训练计算，不能计作训练吞吐。
结束/失败/中断后清理本轮子进程并恢复双卡保活；独立守护覆盖监督进程异常退出，
但 Worker 整体回收时进程内恢复无法继续执行。

启动核验已通过：连续完成 12 次真实参数更新，损失与梯度均为有限值；一条
已确认的规格遗漏购买失败进入更新，训练成本为 -0.65，环境无效标记和原始分数
保持不变。第 10 步的双卡模型、优化器和数据状态已完整保存，峰值已分配显存
约 57.9 GiB；原生 TensorBoard 新增指标、冻结源码哈希和独立后台会话均已核验。
具体证据见本轮输出中的 `startup-verification.json`；这不是最终效果结论。

训练后自动导出选中模型，核验合并权重，再在同一冻结 Chat 入口评测 E3 和 E1。
新配对比较与历史 69.0% 分别报告。一次运行不能证明改进稳定，不预先承诺效果提升。
HDFS 归档与训练/导出/评测完成状态分开；配额异常保留本地产物并标记待归档，
不再让上传失败阻断模型导出和评测。
