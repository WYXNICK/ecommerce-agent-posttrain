# 本次复现的实现与验证

## 范围

流程为 Baseline → SFT → GRPO → Evaluation。
环境为 ShopSimulator v2.1、Reward v3、Observation v2、工具 Schema v2。
使用固定 800/200 SFT 划分，799 条训练轨迹在 24,576 上下文限制内，200 条验证全部保留。
完整配方见 [SFT 说明](sft.md)。原 `docs/sft.md` 的课程训练描述继续保留，不能据此推断本次采用了课程训练。

## 为跑通流程修复的实现

- 安装遵循冻结依赖锁；ShopSimulator 的独立依赖安装不再继承主项目 numpy 覆盖规则。
- 修正环境清单中一个过期源码哈希；环境源码未改动，并通过环境测试和全部教师动作回放核验。
- 修复 GRPO 启动入口未定义变量，预检与实际训练使用相同配置目录及覆盖参数。
- vLLM 启动加入虚拟环境可执行路径，保证编译工具可发现。
- 双卡 GRPO 使用 Ray 单机回环通信和显式 local rank 选卡；实际双卡通信验证通过，解决 HTTP 403 与重复 GPU 映射的启动阻断。
- 当前 veRL FSDP 保存接口不实际使用 HDFS 路径。后台监督进程将完成保存的检查点从 Worker 临时盘归档到 HDFS，日志另存共享目录；训练退出后恢复原 GPU 保活进程。
- GRPO 熵系数仍为 0，关闭不参与策略目标的熵统计，避免零权重熵反向图造成显存不足。
- log-probability 回退使用 `torch.compile(dynamic=True)` 融合已有 log-softmax 和 gather，减少词表中间张量的显存开销。数值对照及双卡完整长度测试见 [GRPO 说明](grpo.md)。
- 根据启动验证中有效奖励组比例偏低、连续补采不足的现象，将每轮补采上限从 3 批提高到 8 批；每轮仍训练 2 个有效问题组、每题 4 条轨迹，保留连续 10 次跳过更新的退出保护。此项属于本次复现的采样预算调整。
- 在创建 LoRA 前固定随机种子，确保适配器初始化也可复现。
- Observation v2 搜索页容量检查覆盖结构化页面。
- GRPO 导出先恢复 FSDP 权重，再将独立 LoRA 合并为可直接服务的模型；缺失或零 alpha 会拒绝导出。
- 对比报告改为根据输入运行计算，不引用旧实验固定结论；同 API 模型名显示阶段名称，任务集合不一致时拒绝比较。

正式训练保留原始 Transformer 算子。可选 FLA 的数值对照未达到预设梯度误差标准，未采用、未加入正式依赖。

## 选点与评分

GRPO 完成 500 次参数更新；每 50 步验证，实际运行覆盖为每 10 步保存。仅按独立 50 题验证集的平均奖励选点，同分取较早步数。
最终 200 题不参与配方调优和检查点选择。
严格成功由完整 `gold_purchase` 且 `reward_valid=true` 等代码条件确定，外部裁判分数单独报告。
GPT-5.5 裁判目前仅讨论可行性，尚未调用或完成本项目的评分校准。
