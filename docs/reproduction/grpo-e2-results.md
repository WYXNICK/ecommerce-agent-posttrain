# GRPO E2：补充重评结果与分析

本报告是 **E2 raw-token 执行协议的补充备份**。项目主结果仍为
[原 Chat 协议结果](grpo-e1-results.md)：SFT 65.5%、上一版 GRPO 66.0%、E1 69.0%。
保留两套完整结果便于复盘协议敏感性；不跨协议比较训练增益，不按模型挑选最高分。
E2 尚未在原 Chat 协议下评测。

## 1. 完成状态与实现范围

E2 从同一 SFT 合并权重新建 LoRA，保留 E1 的失败学习、训练奖励筛组和参数守卫。
本轮统一单次生成上限、累计 response 预算、完整工具消息模板和实际 assistant
token 历史；训练工具描述从环境权威定义加载。具体契约见 [实现说明](grpo-e2.md)。
无 KL loss，学习率 1e-6、LoRA rank 16 / alpha 32、每批 2 题、每题 4 条轨迹。

- 双 H100 80GB 完成连续 1–500 次实际优化器更新，原生进度计时 **10 小时 15 分 06 秒**。
- 1000 条训练任务、50 条独立验证任务、Final-200 隔离；训练诊断无 Final-200 ID。
- 每 10 步保存、每 50 步验证；按验证平均原始 Reward v3 选中 **step 500**，
  验证奖励 **0.4658074063214008**。Final-200 不参与选点，同分取较早步数。
- 模型导出已验证：E2 权重 SHA-256 与 SFT 不同，抽查文本层存在非零 LoRA 更新。
  PEFT 的视觉投影 LoRA 缺失警告已核查：该检查点未训练该投影的 LoRA，合并后
  对应基础参数与 SFT 相同，没有遗漏已训练的视觉适配器。
- 北京时间 **2026-10-06 17:59** 完成本地导出和四模型重评；双卡保活自动恢复。
  首个监督流程在训练完成后因 HDFS 归档失败退出，后处理复用已保存检查点，未重训。

## 2. 重评结果：只在本表内比较

四组使用同一 200 个唯一任务、相同 raw-token 入口，temperature 0、top_p 1、
35 个工具步、每次最多 512 token、上下文 24576、安全余量 512，关闭历史压缩。
累计 response 上限 20480，包含工具模板 token。严格成功仍要求完整有效的
`gold_purchase` 终局；异常与不可验证奖励不从 200 题分母剔除。
三个历史对照直接加载原合并权重，未重新训练。

不能用“验证奖励上升”替代“正式成功率提高”。

## 3. 为什么与主结果不同

任务、环境计分代码、初始 system/user 文本和历史模型权重保持一致，但模型输入
与历史执行方式发生变化，不能把这次重评视为原协议的重复测量：

1. 旧 Chat 入口传完整工具 schema；新的类型化 schema 序列化不保留
   `additionalProperties: false`。工具描述不变，但模型看到的输入 token 已不同。
2. 旧入口根据结构化 assistant/tool 消息重新套 Chat 模板；新入口保留真实生成的
   token，包括空白与 EOS，并追加完整工具反馈模板。
3. 新入口显式执行累计 20480 response 预算；旧入口只有单次输出和完整上下文上限，
   没有相同的累计 response 约束。

例如 E1 的 task 8187：初始 system/user 文本完全相同，旧首轮输入 2062 token，
新首轮 1997 token，相差 65；这是 schema 渲染变化的实际证据。
该模型 tokenizer 默认模板与显式 `enable_thinking=false` 的首轮前缀相同，
没有证据把差异归因于 thinking 开关。

同检查点旧 → 新的成功状态变化：SFT 新增 6 / 丢失 4；上一版 GRPO 新增 7 /
丢失 3；E1 新增 6 / 丢失 7。因此 E1 总分只少 1 题，实际有 13 题成功状态变化。
没有单项消融，不能把所有变化归因于其中某一个协议修改。

## 4. 训练信号与剩余不足

采样 1519 批、3038 个 group，共 12152 条轨迹；实际更新使用 1000 个 group、
4000 条轨迹。6 次重采样跳过事件没有造成实际更新步缺失。
生成 group 中 1780 个奖励恒定、164 个 sampling-invalid 被过滤；其余 1094 个
通过该轮筛组，不能等同于最终进入更新的 1000 个 group。

实际更新保留 **185 条非终局模型失败**，训练奖励均为 `-0.65`：119 条 response
预算耗尽、65 条连续非法动作终止、1 条提前最终答复。生成的 394 条奖励不可验证
轨迹全部未进入更新。模型失败学习链路有真实证据，但这不保证最终指标一定提高。

工具 token 约占实际更新 response 的 **94.48%**，学习 mask 为 0；因此很长的
response 不等于大量模型决策。损失与梯度范数有限，单卡峰值 allocated 约
**60.00 GiB**，未发生 CUDA OOM。训练日志有已捕获的 XML 解析异常和退出阶段
worker 警告，不将“完成训练”表述为“日志完全无异常”。

四模型共 8234 次正式生成的 token 预算全部通过核查。E2 的 5 条非终局错误均为
`ResponseBudgetError`；另有 2 条终局奖励不可验证。后一类案例中，模型直接购买
未选定价格规格轴的商品，价格解析为 `effective_price_axis_unselected`，不算严格成功。
服务/采集/释放错误为零，并不代表奖励不可验证为零。

E2 另有 35 条部分匹配购买，其中 33 条规格未完全匹配、20 条核心功能未完全匹配
（类别可重叠）。下一阶段应先处理模型可归因的规格选择遗漏与约束核验，区分真实
服务故障和模型导致的不可验证购买，再设计独立验证与受控消融；本次没有启动新实验。
Final-200 已用于迭代分析，应作为固定回归集，新的泛化结论需要独立测试集。
